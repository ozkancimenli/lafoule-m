[OmniToolset](https://www.omnitoolset.com) used to be an SMS and workflow-automation SaaS: a Next.js front end, an API on Render, a database, onboarding, billing plans. It worked, and it had no customers. Every path to revenue ran through sales conversations and support — exactly the part of the business I didn’t want to run.

So I rebuilt it around a different question: **what can people use the moment they land, with nobody on my side in the loop?**

---

## The new model: free tools, paid for by attention

The new OmniToolset is a set of single-purpose tools — compress an image, merge PDFs, make a QR code, format JSON. People find them through search, use them, and leave. The site is designed to be supported by ads rather than subscriptions.

That model only works if three things hold:

- **No marginal cost per user.** If every conversion burns server time, traffic becomes a bill.
- **No accounts and no support.** Anything that needs a login creates tickets.
- **A real reason to choose this site** over the hundreds of existing converters.

One technical decision covers all three.

---

## Everything runs in the browser

Every tool processes files on the visitor’s own device. Nothing is uploaded.

- **Images** are decoded into a `<canvas>`, resized or cropped there, and re-encoded with `canvas.toBlob()` as JPG, PNG or WebP. Re-encoding also drops EXIF metadata, which powers a separate tool that strips GPS location from photos.
- **PDFs** are merged, split and created with [pdf-lib](https://pdf-lib.js.org/), which reads and writes PDF structure entirely in JavaScript.
- **Passwords** come from `crypto.getRandomValues`, the browser’s cryptographic random source.
- **QR codes** are generated client-side and can be downloaded as PNG or SVG.

The result: hosting is a static site on Vercel’s free tier, there is no user data to protect or lose, and “your files never leave your device” becomes a genuine selling point — many free converters upload documents to their servers.

Each tool is a client component loaded on demand, so a visitor opening the JSON formatter never downloads the PDF library.

---

## Built for search from the first commit

With no ad budget, Google is the distribution channel. Each tool gets its own statically generated page with:

- a title and description written for what people actually search (“merge PDF files online free”)
- a short how-to and an FAQ, also emitted as `FAQPage` structured data
- links to related tools and to longer guides on the same topic

The site also has a handful of practical guides — combining PDFs on Mac and Windows, choosing between PNG, JPG and WebP, Open Graph image sizes — each one linking to the tool that solves the problem. A sitemap, robots rules, privacy and terms pages and an `ads.txt` route are generated by the app itself.

---

## Two bugs worth remembering

**An empty string broke every page.** The ad script is only rendered when an ad-network ID is configured: `{clientId && <Script … />}`. Without an ID, `clientId` is `''`, and React renders that empty string as a text node inside `<head>`. The server and client HTML no longer matched, hydration failed, React re-rendered the page — and the stylesheet disappeared. The fix was to write `clientId ? <Script … /> : null`. A good reminder that `&&` with strings is not the same as with booleans.

**The old project shape was still in the hosting settings.** The previous version was a monorepo, and the Vercel project still pointed at `apps/web`. The first deployment of the new site failed in one second. Clearing the root directory fixed it.

---

## Where it stands

The site is live with 16 tools and the first guides, and its sitemap is submitted to Google. New sites usually take a few months to earn search traffic, so the plan is simple and steady: add a couple of useful tools at a time, write a guide for every few tools, and keep everything fast and private.

Try it at [omnitoolset.com](https://www.omnitoolset.com).
